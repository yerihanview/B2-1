# B2-1 검수 계획 및 품질 게이트 v1.0

상태: 구현·로컬 자동 검수 결과는 [validation-results.md](validation-results.md) 참조. **원격 CI·사람의 최종 데모 승인은 미확인/대기**. 기준: 공식 미션, 평가항목, docs/spec.md, docs/design.md.

## 검수 원칙
- 공식 평가 체크리스트의 각 항목에 테스트 ID, 증거, 설명 자료를 연결한다. 사람이 평가할 설명의 타당성과 자동 검수 결과를 혼동하지 않는다.
- AI가 구현한 테스트만 신뢰하지 않도록 명세에서 만든 독립 테스트 사례(예상 결과 포함)를 함께 사용한다.
- 불합격을 통과로 포장하거나 예외 항목을 누락하지 않는다.
- 코드 검토는 무작위 전수검토가 아니라 파일 안전성/데이터 경계/아키텍처 변경 등 고위험 지점에 집중한다.

## 테스트 세부 목록
- T01 add: category 등록→대화형 거래 추가→id/저장값 확인. 잘못된 amount/date/type/category는 파일 미변경.
- T02 list: 입력 순서와 날짜 순서 다르게 입력→정렬, 동일 날짜 동률, 기본 20/limit 1/1000, 0/1001 거절.
- T03 search: 기간 양끝, AND 결합, memo 부분일치, tag 정확일치, 결과 없음, 역전 기간 거절.
- T04 summary: 수입/지출/잔액, TOP N 동률, 데이터 없는 월.
- T05 budget: 설정 및 덮어쓰기, 사용률 100.0% 경고 없음/초과 시 경고.
- T06 update: 한 필드/복수 필드, memo/tags 빈 값 초기화, 없는 id, 잘못된 입력, id 유지.
- T07 delete: 기존 id 삭제/없는 id, 나머지 레코드 무결성.
- T08 export: month 또는 기간 필수, 헤더 정확성, overwrite 안전 정책, 데이터 0건.
- T09 import: 한국어/quoted CSV, 새 id 부여, categories 검증, 두 번째 import 시 중복 재등록되는 현재 정책 경고.
- T10 세 파일 최초 생성, 별도 프로세스 재시작, JSONL 재파싱.
- T11 category 등록/중복/사용 중 삭제/미사용 삭제.
- T12 월 예산 사용률/초과 경계/예산 없는 월.
- T13 UTF-8 CSV 헤더, 특수문자, round-trip.
- T14 오류 메시지(원인·힌트) 및 traceback 없음.
- T15 subprocess exit code 0/2/3/4.
- T16 저장 실패를 monkeypatch 또는 의존성 주입으로 강제해 원본 bytes/hash 보존; 원자 교체 성공.
- T17 100,000건에서 list/search 결과 상한, iterator 실제 순회, tracemalloc 최대 메모리 기록(N/K 증가에 따른 비용과 ID 집합 비용을 구분하며 사후 임의 합격 상한을 만들지 않음).
- T18 decorator 적용 대상 및 원래 함수 계약 보존(`functools.wraps`).
- T19 혼합 CSV, UTF-8 깨짐, 필수 컬럼 누락, 알 수 없는 category → 처리 0건 및 오류 위치.
- T20 파일 손상/중복 JSONL ID, stale lock → 자동 데이터 수정 없이 오류.

## 구현 전 게이트 G0
1. 현재 정리 문서의 평가 요구→A01~A16 매핑 확인. 첨부 공식 원문·평가표 텍스트 대조 완료(2026-11-02); 삽입 이미지는 대조 범위 밖. 원문은 저장소에 올리지 않는다.
2. docs/design.md ADR, docs/spec.md 입력·출력·오류 계약 확정.
3. 외부 패키지 사용금지, 최소 3 모듈·2 클래스 조건 확인.
4. 테스트 예제 데이터와 기대값 마련. **명세 기반 개발 준비와 공식 원문 대조 상태를 구분하며 구현 검수는 미완료**.

## 구현 후 게이트 G1/G2
- G1 자동: `python -m unittest discover -s tests -v` 전체 성공, 표준 라이브러리 외 런타임 의존성 없음, 간단한 CLI smoke 확인, 명세와 일치.
- G2 인간: 15분 내외 데모를 통해 거래/카테고리/예산/CSV/영속성/오류 1회 이상 실제 검수; A08~A16 설명 가능한지 점검.
- G2 승인 전 모든 A01~A16에 **실행 근거 링크 또는 설계 설명 근거** 첨부. 실패/미검증은 그대로 공개한다.
- PR CI는 필수 검수 흐름으로 유지한다. Python 3.10에서 실제 테스트 수 > 0, 실패·오류 0, 전체 스킵 아님을 확인한다. 실제 Actions 실행 전에는 CI 통과를 주장하지 않는다.

## 증거 최소화
최소: 최종 테스트 실행 로그 1개, 기능 시연 메모 또는 실행 결과, 파일 3종 재실행 확인, 의도된 오류+exit code 증거, 핵심 설계도 1개. 필요 없는 전 과정 스크린샷 금지.


## CI 실패 처리 및 병합 게이트

[실패 처리 정책](failure-policy.md)에 따라 PR 검수 실패→AI 수정(동일 결함 3회 이하)→전체 회귀→재검수→인간 승인을 적용한다. 위험한 데이터 변경/명세 충돌 시 인간 판단이 우선한다. GitHub Branch protection/Ruleset이 설정되기 전에는 병합 차단이 기술적으로 강제되지 않는다.

## 독립 검증과 실행기의 구분

독립 검증 담당은 명세에서 입력·기대값을 먼저 작성하고 검수 테스트와 결함 보고를 소유한다. 구현 파일은 수정하지 않는다. 개발 담당은 구현과 개발 단위 테스트를 소유한다. GitHub Actions는 두 테스트를 실행하는 실행기이며 기대값을 설계하거나 판정 기준의 독립성을 보증하지 않는다.

통합 담당은 고정된 통합 SHA에서 양쪽 테스트를 실행한다. 결함 기록: 검수 ID / 재현 SHA / 입력·명령 / 기대·실제 / 종료 코드 / 원본 보존 / 수정 시도 1~3 / 재검증 SHA. 실패·오류·스킵·미실행을 별도로 기록하고 필수 검수 스킵은 G1 통과로 인정하지 않는다.

## 보너스 필수 검수 B01~B04

- B01: backup 전체 도움말, timestamp+UUID ZIP, 원본 바이트·manifest 해시/크기, 기본 3파일/선택 규칙 파일 포함, 잠금/이전 백업/기타 파일 제외, 반복 실행 시 기존 ZIP 보존, 별도 가상 디렉터리 복구 후 CLI 동일 결과. 손상·잠금·write/flush/fsync/발행 전 실패 시 원본 보존 및 완성 ZIP 없음, 발행 후 실패는 반영됨 안내.
- B02: recurring 도움말 전수, add/list/remove 영속성·없는 ID·입력 경계·사용 카테고리 삭제 거부, 31일의 윤년/비윤년/30일 월 보정, 같은 월 재실행 skip, 다른 월 생성, 수정 후 출처 유지, 생성 거래 삭제 뒤 새 ID 재생성, 규칙 삭제 뒤 과거 거래 보존. 규칙/출처 손상과 중복 검출. apply 실패 시 전건 원본 보존, 0규칙/전건 skip 시 불필요한 거래 교체 없음. CSV 왕복은 기존 스키마·비멱등성 계약을 유지.
- B03: 서로 다른 길이의 ID/type/category/amount와 한글·결합문자 memo에서 구분자 표시 위치와 금액 오른쪽 끝 일치. 메모 newline/tab 제어문자도 한 행으로 출력하고 원본 보존. list/search 정렬·limit 회귀.
