# B2-1 전체 설계서

> 상태: 초안 · 아직 승인되지 않은 설계

## 목표
용돈 기입장 CLI의 책임 분리, 데이터 안전성, 테스트 가능성을 설계한다. 상세 요구사항은 `docs/spec.md`, 공식 항목은 `docs/acceptance.md`에서 관리한다.

## 제안 계층
`CLI → Service → Repository → Model/파일`

- CLI: 입력 해석, 출력, 사용자 오류, 프로세스 종료 코드
- Service: 거래·카테고리·예산 규칙과 비즈니스 검증
- Repository: 영구 저장, CRUD, 데이터 스트리밍 및 교체 처리
- Model: 데이터 타입, 필드 의미, 도메인 불변 조건

## 설계 결정 대기
1. 거래 ID, 날짜, 금액, 카테고리, 메모의 스키마
2. 기본 포맷(JSONL/CSV) 및 거래/카테고리/예산 파일 3종
3. 최신순 정렬과 스트리밍을 동시에 만족할 방법
4. update/delete 원자적 교체 및 장애 복구
5. import의 검증·롤백 정책
6. 테스트 주입 지점과 모듈·클래스 책임 경계

각 결정은 **선택 / 대안 / 근거 / 검수 방법 / 결정일**로 기록한다.
