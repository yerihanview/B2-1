# B2-1 구현·검증 운영 계획 v1.0

상태: 실행 계획 및 운영 계약. 실제 실행 결과는 [validation-results.md](validation-results.md) 참조. 상세 명세는 docs/spec.md, 하네스 지침은 AGENTS.md.

## 작업 단위
1. 프로젝트 골격, dataclass, 오류 클래스, CLI 도움말. 검수 S01/S02/S04 및 T15 기반.
2. 저장소의 파일 생성/읽기/검증/안전한 교체/잠금. T10/T16/T20 기반.
3. 카테고리·예산·거래 서비스와 add/update/delete. T01/T05/T06/T07/T11/T12.
4. generator 기반 list/search/summary 및 bounded heap. T02/T03/T04/T17.
5. CSV import/export 및 전체 롤백. T08/T09/T13/T19.
6. 예외 decorator, 모든 메시지·종료 코드의 일치 검증. T14/T15/T18.
7. 전체 회귀, 10만 건 병목 측정, README, 최종 시연. P01, A01~A16.

## 개발 모드
- 사용자는 각 기능을 직접 손으로 붙여서 개발할 의무가 없다. 승인된 전체 설계를 기준으로 AI에 구현을 맡긴다.
- 구현 내부는 각 단위에서 테스트·재시도를 반복. 데이터 안전성 기능을 먼저 안정화한 뒤 범위를 확장한다.
- 각 단위 완료는 테스트와 근거를 기록한 경우에만 인정한다.
- 설계 변경 요청 시 ADR 및 명세/검수 기준을 먼저 갱신한다.

## 품질 기준
- 필수 테스트 전부 성공, 미실행/결함 없음 확인.
- 공개 API 타입 힌트, 모듈 책임, 제너레이터·데코레이터 적용을 정적/동작 검사로 확인.
- 수동 데모에서 정상·오류·재시작·파일 보존 확인.
- 10만 건의 측정 데이터는 실제 관측 전에는 절대값 주장 금지.

## 하네스 연구 측정
기능 검수 16개 중 통과 비율, 구현 후 재작업 횟수, 사용자 승인 요청 횟수, 총 수행시간, 테스트/문서화에 쓴 시간, 추가 자동화의 효과를 기록. 측정은 필요한 만큼만 간단히 수행한다.


## PR/CI 운영 원칙

기능 구현은 작업 브랜치→PR→GitHub Actions 자동 테스트→실패 시 수정·재검수→인간 승인→병합 순서. 실패 원인과 최대 3회 자동 수정 시도, 예외 에스컬레이션은 [failure-policy.md](failure-policy.md)를 따른다. CI 자체는 코드 수정 기능이 없으므로 개발 에이전트 연계는 별도 구성해야 한다.

## 역할·병렬 작업·증거 계약

설계 담당은 명세·ADR·검수 계약, 개발 담당은 구현·단위 테스트·수정, 독립 검증 담당은 명세 기반 검수 테스트·재현·재검증, 통합 담당은 통합 SHA와 최종 증거를 소유한다. 독립 검증 담당은 구현을 수정하지 않는다. GitHub Actions는 테스트 실행기다.

기존 격리 체크아웃을 기본으로 사용한다. 읽기 전용 검토는 공유할 수 있지만 서로 다른 브랜치의 쓰기 작업은 같은 디렉터리에서 병렬 수행하지 않는다. 병렬 쓰기는 별도 격리 환경/체크아웃으로 분리한다. 사용자가 명시적으로 요청하지 않으면 worktree를 생성하지 않는다. docs/*, feat/*, verify/* 브랜치와 PR을 사용하고 통합 SHA에서 전체 회귀를 재실행한다. main 직접 구현 push 및 자동 병합은 하지 않는다.

계약 보강 → 골격/모델/help → 저장소/잠금/장애 검수 → 서비스/재시작 → 조회/CSV → 통합 회귀/10만 건/README/데모 순서로 진행한다. 개발과 동시에 독립 검증자는 명세 기반 입력·기대값을 준비한다. 최종 로그에는 SHA·Python·명령·실행 수·결과·종료 코드를 기록하며 가상 데이터만 사용한다. 실패 기록은 failure-policy.md의 동일 결함 3회 상한을 따른다.

## 보너스 필수 범위 추가

사용자 요청으로 B01~B04 전체를 구현한다. 계약(spec/design/acceptance) → 개발 및 독립 검수 → 양 Python 버전 전체 회귀 → 가상 데이터 backup/recurring/정렬 데모 → 고정 SHA 증거·GitHub 기록 순서로 진행한다. 원자성은 기존 구현을 신규 쓰기 경로로 확장한다. 기존 파일 자동 변환이나 실제 데이터 삭제는 하지 않는다.
