# B2-1 구현·검증 운영 계획 v1.0

상태: 실행 전. 상세 명세는 docs/spec.md, 하네스 지침은 AGENTS.md.

## 작업 단위
1. 프로젝트 골격, dataclass, 오류 클래스, CLI 도움말. 검수 S01/S02/S04 및 T15 기반.
2. 저장소의 파일 생성/읽기/검증/안전한 교체/잠금. T10/T16/T20 기반.
3. 카테고리·예산·거래 서비스와 add/update/delete. T01/T05/T06/T07/T11/T12.
4. generator 기반 list/search/summary 및 bounded heap. T02/T03/T04/T17.
5. CSV import/export 및 전체 롤백. T08/T09/T13/T19.
6. 예외 decorator, 모든 메시지·종료 코드의 일치 검증. T14/T15/T18.
7. 전체 회귀, 10만 건 병목 측정, README, 최종 시연. P01, A01~A16.

## 개발 모드
- 사용자는 각 기능을 직접 손으로 붙여서 개발할 의무가 없다. 승인된 전체 설계를 기준으로 AI에 구현을 맡긴다.
- 구현 내부는 각 단위에서 테스트·재시도를 반복. 데이터 안전성 기능을 먼저 안정화한 뒤 범위를 확장한다.
- 각 단위 완료는 테스트와 근거를 기록한 경우에만 인정한다.
- 설계 변경 요청 시 ADR 및 명세/검수 기준을 먼저 갱신한다.

## 품질 기준
- 필수 테스트 전부 성공, 미실행/결함 없음 확인.
- 공개 API 타입 힌트, 모듈 책임, 제너레이터·데코레이터 적용을 정적/동작 검사로 확인.
- 수동 데모에서 정상·오류·재시작·파일 보존 확인.
- 10만 건의 측정 데이터는 실제 관측 전에는 절대값 주장 금지.

## 하네스 연구 측정
기능 검수 16개 중 통과 비율, 구현 후 재작업 횟수, 사용자 승인 요청 횟수, 총 수행시간, 테스트/문서화에 쓴 시간, 추가 자동화의 효과를 기록. 측정은 필요한 만큼만 간단히 수행한다.
