# B2-1 미션 수행 전략

> 상태: 수행 전략 v0.1 · 2026-11-01  
> 근거: Project Sources의 `B2-1 미션.md`, `B2-1_평가항목.md`  
> 원문/평가표와 이 문서가 충돌하면 원문과 평가표를 우선한다.

## 1. 미션과 목표의 구분

- **목표 A — 공식 미션 달성:** Python 기반 용돈 기입장 CLI를 요구사항에 맞게 구현하고, 핵심 기술의 구조·동작·설계 이유를 이해하여 동료 평가에 대응한다.
- **목표 B — 개인 연구:** 명세 중심 AI 개발 방법론과 최소 하네스를 실험하여 품질 좋은 결과물을 만드는 운영법을 학습한다.
- 목표 B는 공식 평가 대상이 아니며, 목표 A를 위한 시간을 과도하게 잠식해서는 안 된다.
- 공식 학습시간: 60시간. 세부 시간 배분은 상세 계획에서 조정한다.

## 2. 운영 원칙

1. **최종 산출물과 데모를 먼저 설계한다.** 무엇을 구현·검증·설명할지 정한 뒤 작업한다.
2. **전체 구조·동작 원리 중심으로 학습한다.** 문법 암기나 일괄적인 코드 줄별 해설은 기본 활동으로 삼지 않는다.
3. **사람은 요구사항, 아키텍처, 명세, 통과 조건, 최종 승인에 책임을 진다.** AI에 코드 작성·테스트 실행·수정을 위임하되 사람의 설계 판단을 대체하지 않는다.
4. **검수 기준은 구현 전에 정의한다.** 테스트는 요구사항과 독립적으로 대조하며, 자동 테스트 통과만으로 모든 품질이 보장됐다고 간주하지 않는다.
5. **일괄 구현을 기본으로 하되 내부 개발·검증은 반복적이다.** 중간 실패에 따라 설계를 갱신할 수 있으며 변경 이유를 기록한다.
6. **B3-1 회고를 반영한다.** 불필요한 로그/캡처 대량 수집, 과도한 보조 자동화, 무지성 따라하기를 피한다.
7. **증거 중심 문서화.** 사용자가 실제 실행·검수에서 수집한 증거만으로 README, 도식, 데모 자료를 작성한다. 수행하지 않은 테스트를 통과한 것처럼 서술하지 않는다.
8. **GitHub를 작업 기준 저장소로 한다.** 설계·명세·검수·하네스 문서 및 코드 변경을 버전 관리한다. 설계 변경 시 관련 명세와 테스트도 갱신한다.

## 3. 우선 확정할 산출물

- 실행 가능한 Python CLI 프로그램과 영구 저장 데이터 체계
- `README.md`: 설치·실행, 명령 예시, 설계 요약, 확인된 검증 결과
- `docs/design.md`: 아키텍처 및 주요 설계 선택
- `docs/spec.md`: 기능·입출력·오류·파일 스키마 계약
- `docs/acceptance.md`: 평가표 추적과 검수 게이트
- `AGENTS.md`: AI 작업 지침 및 허용·금지 범위
- `tests/`: 자동 검증
- 데모 시나리오·핵심 도식은 필요에 따라 `docs/demo.md`로 작성한다.

## 4. 최종 데모 초안 (약 15분, 공식 시간 요건 아님)

| 구간 | 분 | 주요 확인 |
| --- | ---: | --- |
| 기능 및 영속성 | 6 | 거래 add/list/search/summary/update/delete, 카테고리, 예산, CSV import/export, 재실행 후 유지, 오류 메시지와 비영(非0) 종료 코드 |
| 구조·안전성 | 3 | 모듈/클래스 책임, 저장소 추상화, update/delete 파일 교체 정책 |
| 주요 기술 | 3 | 제너레이터 스트리밍, 데코레이터 공통 기능, 타입 힌트의 실질적 활용 |
| 설계 판단 | 3 | JSONL과 CSV 비교, 10만 건 병목·개선, 잘못된 CSV 행 처리·롤백/부분 성공 |

데모 내용은 테스트로 대체하지 않는다. 모든 명령을 시간 내 반복할 필요는 없으나 평가 체크리스트의 각 항목을 실행 또는 설명과 연결한다.

## 5. 아키텍처 초안 (초기 검토 기록; 하단 확정 결과 우선)

- **CLI:** 명령 파싱·출력·입력 오류·종료 코드
- **Service:** 거래/카테고리/예산 규칙, 검색·요약, 검증
- **Repository:** 영구 저장, 스트리밍 읽기, 안전한 파일 갱신 (CSV 변환은 확정 설계의 csv_io.py)
- **Model:** 데이터 구조와 타입 계약

초기 설계 가설: 내부 저장 JSONL, CSV는 import/export, 금액은 정수, 사용 중 카테고리 삭제 거부, 파일 갱신은 임시 파일+교체, import는 전체 검증 후 반영. 이는 구현 전에 원문에 대조해 확정하며, 원문에서 강제한 선택으로 주장하지 않는다.

## 6. 검수·하네스 원칙

- 평가표 항목 1(기능·영속성·오류), 2(모듈·클래스·파일 안전성), 3(제너레이터·데코레이터·타입), 4(포맷·10만 건·가져오기 오류 정책)를 각각 테스트 및 설명 근거와 연결한다.
- 기능 테스트와 별개로 파일 손상, 잘못된 입력, 재시작, CSV 스키마/인코딩, 종료 코드, 대용량 데이터 등 경계 조건을 검증한다.
- 사람이 승인해야 할 사항: 요구사항 해석, 아키텍처의 적정성, 설명 가능성, 위험한 데이터 처리 및 최종 데모.
- 하네스 효과는 검수 통과율, 결함/재작업 횟수, 인간 개입, 총 소요 시간과 보조 작업 비용으로 회고한다. 숫자는 실제 관찰 후 기록한다.

## 7. 수행 단계와 완료 게이트

1. **미션 분석·데모 설계:** 평가항목-증거 연결표 완성
2. **기술 개념 지도:** 구조, 파일 영속성, 스트리밍, 데코레이터, 타입, 예외 원리 설명 가능
3. **설계·상세 명세:** 아키텍처 결정과 명령·파일·오류 계약 확정
4. **검수 기준·하네스:** 통과 조건, 자동 테스트, AI 작업 규칙 확정
5. **AI 구현·검증:** 실행, 자동 테스트, 수정과 재검증 수행
6. **데모·문서·회고:** 실제 근거로 산출물 완성, 목표 A/B 별도 평가

다음 게이트에 필요한 산출물이 없으면 편의상 '완료'로 표시하지 않는다.

## 8. 당시 열려 있던 결정 (초기 검토 기록)

- CLI 옵션 표기: 미션 원문에서 `--`와 `-` 표기가 충돌한다. 명령 예시를 근거로 이중 하이픈을 우선 검토하되 `docs/spec.md`에서 최종 결정·근거를 기록한다.
- 최신순 목록과 스트리밍 읽기 요구를 동시에 만족시키는 저장/인덱스 방식
- 파일 갱신 원자성, 다중 파일 갱신 정합성, 복구 정책
- CSV 오류 행 처리(전체 롤백 또는 부분 성공)와 사용자 리포트
- 테스트 자동화 수준 및 특정 에이전트 도구 선택

## 9. GitHub 문서 운영

- 이 전략 문서는 우선 기준으로 등록한다. 다른 문서의 초안은 확정 명세로 오인하지 않는다.
- 핵심 결정 변경 시 문서→테스트→코드→데모 설명의 연쇄 정합성을 검토한다.
- 실제 구현에서는 명세 또는 테스트 미충족을 이유와 함께 기록하고 AI 수정 루프를 실행한다.
- 소스에 확정된 요구사항은 임의로 삭제하거나 완화하지 않는다.


## 설계 확정 결과 (2026-11-02)

초기 전략의 '열려 있는 결정'은 후속 설계 과정에서 다음과 같이 결론 냈다. 결정 이유·대안·한계는 [design.md](design.md) ADR-01~15에 기록했다.

- 내부 JSONL/외부 CSV, 카테고리 선등록, 양의 정수 금액, UUID 거래 ID.
- list/search 최신순은 날짜 내림차순+동일 날짜 원본 파일 순서 역순; 기본 20건·최대 1000건의 bounded heap 스트리밍. 선택 힙은 O(K), 전체 중복 ID 검증 집합은 O(N)이며 전체 명령 O(K)를 주장하지 않는다.
- 파일 변경은 임시 파일·fsync·os.replace, 단일 사용자 배타 잠금; 다중 파일 원자적 트랜잭션은 지원 범위 밖.
- CSV import는 전건 검증·전건 롤백, export는 CSV 스키마/월 또는 기간 필수.
- CLI는 이중 하이픈(`--`) 채택. 원문 기능 요구사항과 예시를 우선하고, 제약사항의 단일 하이픈 표기 충돌은 ADR-12로 보존.
- 최종 문서 체계: [design.md](design.md), [spec.md](spec.md), [acceptance.md](acceptance.md), [demo.md](demo.md), [learning-map.md](learning-map.md), [implementation-plan.md](implementation-plan.md), 루트 [AGENTS.md](../AGENTS.md).

**상태 구분:** 설계와 검수 기준 문서 작성은 완료. 실제 코드 구현, 테스트, 성능 측정, 데모 수행과 최종 승인은 아직 진행하지 않았다.
